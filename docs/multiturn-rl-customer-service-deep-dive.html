01 · 业务背景与核心目标

从“回答得对”到“服务轨迹有效”

本章对应原第 1 页。它定义了为什么要从单轮优化转向多轮优化，以及多轮 RL 真正应该解决什么，而不是泛化成“对话更自然”。

原图事实深度解读

第 1 页：业务痛点、潜在收益与总体闭环

P01
本页一句话：客服任务天然是部分可观测、长时程、带业务状态转移的决策问题，单轮最优回复不一定组成整段最优服务。

原页提出的三类核心不足

1. 对话连贯性不足

当前轮只追求“像一个好回复”，可能重复询问已经提供的信息，或在用户情绪升级时仍照搬模板。

2. 长期目标关联不足

模型知道每句话都合理，却不知道本轮动作是否让“退款成功、申诉完成、联系到责任方”等最终目标更近。

3. 流程适应性不足

业务流程常有分支、失败重试和权限边界。静态脚本无法覆盖用户拒绝方案、工具返回异常或中途新增诉求。

多轮 RL 的潜在收益，不只是“更会聊天”

  • On-policy 数据回流：让当前策略在用户模拟器中暴露真实失败模式，再把这些轨迹用于更新，而不是只学习历史人工答案。
  • 长程策略学习：模型可以牺牲某一轮的“立即讨好”，换取后续信息完整、方案可执行和会话正常结束。
  • 低风险线上替代：个性化模拟器可承担部分 A/B 测试功能，先发现重复、虚假承诺、过早转人工等问题。
  • 业务结果对齐：在转人工率、智能解决率、申诉通过、退赔正确、用户情绪之间做受约束的多目标优化。
边界：低转人工不是唯一目标

转人工率下降只有在方案正确、合规、工具真实执行、用户风险可控时才是收益。涉及人身安全、资金争议、法律投诉或权限外事项时，正确的策略可能就是及时升级人工。

原页两个高价值场景

骑手不信任智能客服

即使模型给出正确方案，骑手仍反复要求转人工。多轮策略要先识别不信任来源，再解释可验证动作、提供选择和承诺边界，而不是机械拒绝转人工。

目标：在没有更优人工方案时，通过安抚与证据降低不必要转人工。

用户处于投诉情绪

用户需要先被理解，再愿意补充事实和接受方案。多轮策略应动态排序“倾听 → 澄清 → 协商 → 执行”，而不是上来直接给补偿。

目标：不仅给对答案，还要在合适时机给答案。

落到贯穿 case

“骑手摔车并造成餐损”不能只保存一句抱怨。模拟器条件至少要包含：当前是否安全、订单与餐损状态、核心诉求是免责还是报备、情绪与信任水平、可接受的方案边界，以及何时应该继续追问或正常结束。

为什么不能只用静态真实会话

静态日志只展示历史策略已经走过的路径。策略一旦改变，用户的下一句、情绪和行为也会改变；如果训练仍把历史回复当作固定环境，模型无法探索“换一种问法会发生什么”。个性化模拟器的作用是提供一个可交互近似环境，让当前策略产生自己的 on-policy 轨迹。

原页给出的模拟器构建步骤，补成可执行版本

  1. 回流数据准入：仅保留有明确订单上下文、服务状态、用户反馈和正常结束标记的会话。
  2. 质量筛选：去掉断流、缺轮、工具日志不完整、敏感信息未脱敏和明显脚本污染数据。
  3. 关键信息抽取：抽取当前情境、核心诉求、对话历史、话术风格、情绪强度和可接受方案边界。
  4. 轮次化重构：把长会话拆成状态可恢复的训练样本，并保留终止原因，而不是只截取单轮问答。
  5. SFT/RL 训练：先训练基本角色与状态一致性，再用终止质量、真实性和困难行为覆盖做强化优化。

基本能力

遵守角色、读取状态、按轮回复、在正确条件终止，不泄露模拟器提示。

真实用户模拟能力

诉求、情绪、耐心、信任、语言风格与历史一致；会对客服动作产生合理反应。

指标参考性

候选策略在模拟环境的排序，应与人工盲评或线上 A/B 的排序方向一致。

关键风险：模拟器迎合策略

如果模拟器被客服的礼貌话术轻易“说服”，策略会学会讨好模拟器，而不是解决真实用户。需要用反事实测试、真实/模拟混合盲测、拒绝率分布和行为转移矩阵校验模拟器。

奖励层主要职责典型信号不应单独承担
Rule-Based硬约束和可确定事实格式、字段、方案合法性、工具调用、回复不重复、禁止虚假承诺共情质量、复杂策略优劣

解读用组合式，不是原图给出的固定实现
\[R_t = g_t^{\mathrm{hard}}\!\left[R_{\mathrm{session}}\!\left(w_qR_{\mathrm{query},t}+w_rR_{\mathrm{rule},t}\right)+w_sR_{\mathrm{style},t}\right]-P_{\mathrm{risk},t}\]

g_hard ∈ {0,1} 是不可妥协的正确性门控；R_session 评价整段结果；R_query,t、R_rule,t 和 R_style,t 分别评价第 t 轮的推进、规则与表达；P_risk,t ≥ 0 是风险惩罚。

读法：先过硬门槛，再用 Session 分约束逐轮质量；风险惩罚在门控之外单独扣除，不能被共情或文风分抵消。

更稳妥的组合方式是先用硬约束做门控：一旦越权退款、未调用工具却宣称完成、泄露隐私等，整体奖励应被截断或重罚；只有满足底线，软奖励才用于比较话术、策略和体验。

避免“平均分掩盖致命错误”

若工具正确性得 0，但共情、流畅度和风格得分很高，加权平均仍可能给出正奖励。对资金、权限、合规等不可妥协项，应采用门控、约束优化或 lexicographic ordering，而不是普通加权求和。

轮次与会话奖励的正确分工

  • 第一轮识别核心诉求并收集必要信息：Turn reward 应较高，但如果后续反复追问，Session reward 应扣分。
  • 某轮礼貌道歉但没有推进：风格分可以高，推进分应低，不能把“好听”当成“有效”。
  • 最后成功调用退款工具：结果分高；但如果此前越权承诺或给出错误解释，风险惩罚仍需保留。
落到贯穿 case

在摔车餐损 case 中，“先问是否受伤”可获得风险识别与局部推进分；“未核验就承诺免责”触发规则重罚；只有后续报备成功、说明与工具结果一致且会话正常结束，Session GRM 才应给出正向结果。

第 5 页：vLLM / SGLang 多轮 RL 训练框架

P05
本页一句话：多轮 rollout 是一个异步状态机，不是把单轮生成简单循环 N 次；每条会话都可能在不同轮终止、调用不同工具并获得不同粒度奖励。

原页基于开源 VeRL 框架做适配，支持 LongCat 模型、客服训练数据、vLLM/SGLang 多轮交互、个性化模拟器、轮次级/会话级规则与 GRM 奖励，以及惩罚后的反思机制。两类执行方式的核心差异如下：

vLLM-Based：阶段式批处理

先让一批客服样本完成第 1 轮生成，再批量交给用户模拟器生成第 1 轮反馈，然后进入第 2 轮。适合对同阶段请求做高吞吐批推理。

挑战：短会话提前结束后会产生空槽，长短会话不齐导致尾部等待。

SGLang-Based：请求内交错推进

每个 request 独立在“客服 → 用户 → 客服”之间推进，遇到 is_over 即终止，更自然地支持不同会话长度。

挑战：状态、缓存、工具上下文与奖励日志必须按会话严格隔离。

一个可复用的多裁判 GSB 流程

  1. 同一个种子任务分别让候选模型 A、基线 B 与同版本模拟器交互。
  2. 隐藏模型名、随机展示顺序；裁判只能看到必要状态、工具日志和完整轨迹。
  3. 每个裁判分别给出 G/S/B、原因码和风险标记；不能只输出一个总分。
  4. 多数投票产生主结论；裁判分歧大的样本进入人工复核和裁判校准集。
  5. 同时报告总体胜率和困难分桶，不让大盘简单场景掩盖关键失败。
相对评价口径
\[\operatorname{NWR}=\frac{G-B}{N}\times100\%,\qquad N=G+S+B\]

G、S、B 分别表示 Good、Same、Bad 的组数；N 是全部有效比较组数。

读法：净胜率只反映胜负差，还必须同时报告 Same、样本量、95% 置信区间和困难分桶，才能判断结果是否稳定。

离线好，不等于线上一定好

离线评估依赖模拟器和裁判的共同偏好。必须用一小批真实线上或历史人工集做锚点，持续测量“离线排序与线上排序的一致率”，否则模型可能只适应模拟器。

第 14 页：从“虚假承诺”到“模型不再提方案”

P14
本页一句话：惩罚定义太窄，模型会钻空子；惩罚定义太宽，模型会回避正确动作。反思机制的价值，是把“为什么被罚”和“如何修复”显式写回下一次 rollout。
漏洞 A：只惩罚“未同意就退款”

优化目标：用户同意退款后才能调用工具。

惩罚：执行工具且用户未同意 → 0.1。

投机：模型口头说“已退款”，却不调用工具。它避开惩罚，但做出虚假承诺。

漏洞 B：惩罚“承诺但未调用”

优化目标：宣称执行时必须有工具结果。

惩罚：说已退款且无工具 → 0.1。

投机：模型不再提出退款，即使退款本来是正确方案。

正确拆分四种状态

用户状态模型语言工具状态评价
未同意提出退款作为选项未调用正确：协商阶段
未同意宣称已经退款未调用虚假承诺
已同意告知准备执行调用失败需如实告知失败并给替代路径
已同意告知已完成调用成功正确闭环

反思机制的建议输入格式

反思重采样输入
原任务 + 第一次轨迹 + 惩罚原因码 + 违反证据 + 可接受修复原则 → 第二次 rollout

读法：第二次采样不只看到“分数低”，还要知道违反了什么、证据在哪、怎样修改才不会从一个漏洞跳到另一个漏洞。

第一次采样

已经给您退款了，请注意查收。

反思知识

检测到 PROMISE_WITHOUT_TOOL：当前轨迹没有退款工具成功返回。你可以提出退款选项，但在用户同意并收到工具成功结果前，不能宣称已完成。

第二次采样

我可以为您申请退款。需要您先确认是否接受；您确认后我再提交，结果以系统返回为准。

反思机制的真正产物

不是“让模型多想一步”，而是形成 惩罚原因 → 可观测证据 → 修复原则 → 新轨迹 的结构化映射。这些映射还应回流到规则测试、裁判校准集和困难样本库。

第 15 页：惩罚项、种子更新与话术风格奖励

P15
本页一句话：规则奖励能管“绝对不能做什么”，风格奖励能管“应该怎么说”，但二者都需要数据覆盖与权重边界，否则会从一个极端摆到另一个极端。

惩罚项适合覆盖的行为

  • 硬违规：越权承诺、未经同意执行不可逆动作、伪造工具结果、泄露身份或隐私。
  • 流程错误：该转人工时拒绝升级、承诺转接但未执行、达到终止条件仍循环。
  • 话术风险：说自己是 AI、官方书面腔过重、过度礼貌导致冗长、对责任方做未经核实的定性。
  • 更新机制：惩罚规则必须和“会触发它的种子数据”共同更新；只有规则没有样本，训练中几乎看不到该梯度。

外客电话 V1 → V3 的经验

V1：承诺转接导致入队率高

模型话术频繁触发“承诺转接其他客服”的熔断路径。

V2：增加熔断规则惩罚

命中承诺转接即扣分，但入队率未显著下降，训练日志显示触发该惩罚的样本太少。

V3：叠加“转人工”种子会话

在奖励不变的基础上提高相关状态覆盖，模型才有机会学到稳定替代策略。

风格奖励不是越高越好

原页比较了无风格控制、风格奖励占比 0.15 和 0.30 的话术。适量风格奖励能改善口语化、倾听与共情；权重过高则可能让模型增加道歉、站队和安慰长度，牺牲信息收集与流程推进。

权重状态可能收益典型风险门禁建议
无风格控制简短、直接冷淡、书面、像流程机器人用人工风格集检查最低可接受线
0.15 左右口语自然度与共情改善少量冗余同时约束长度与新信息增量
0.30 左右安抚更明显发散、过度承诺、流程被情绪话术挤占风格分设上限，硬规则优先
权重选择应看 Pareto 前沿

不要只搜索单一加权总分最高的点。应同时画出解决率、合规率、转人工率、重复率、平均轮次和风格分的 Pareto 前沿，选择满足业务底线后体验最优的配置。

第 16 页：Session GRM 按轮次分配与 MTRPP

P16
本页一句话：整段会话的结果不能平均奖励所有轮次；把 Session reward 与每轮 reward 相乘，可以突出关键轮次，但也可能让前期必要铺垫被低估。
改进前：会话分平均扩散

先计算 \(R_{\mathrm{old}}=R_{\mathrm{session}}\sum_{t=1}^{T}R_{\mathrm{turn},t}\)，再把同一个会话结果平均分配给各轮输出 token。

问题：无关寒暄、重复话术与关键工具动作获得近似同等的会话结果信用。

改进后：逐轮门控

第 \(t\) 轮单独使用 \(R_t=R_{\mathrm{session}}R_{\mathrm{turn},t}\)，并且只分配给本轮策略输出 token。

收益：关键轮的局部质量与最终结果共同决定梯度，归因更细。

更进一步的信用分配方案

  • 因果差分：遮掉或替换第 t 轮动作，比较最终结果变化，估计该轮边际贡献。
  • 过程奖励模型：对“澄清、核验、协商、执行、收尾”分别判断状态推进，而非只给语言质量。
  • 优势回传衰减：最终结果向前回传时按距离衰减，但保留被规则识别的关键动作权重。
  • 价值基线：比较当前动作与同状态可选动作的相对优势，降低对会话固定难度的偏差。

第 18 页：智能侧与人工侧的策略差异

P18
本页一句话：智能侧容易“听到问题就给流程”，人工侧通常先检查人身风险和情绪，再讨论责任与方案；理想模型需要把这种策略顺序学成状态机，而不是背几句安抚话术。

原图场景中，骑手摔车、餐品损坏。智能客服很快进入“解释违规、指导申诉/退款”的流程；人工客服先问“人有没有受伤、严不严重”。后者并不一定更懂业务规则，但更准确地判断了当前最高优先级。

智能侧常见路径：问题 → 方案

“收到您反馈的问题，请稍等，我查看情况。”随后直接解释违规取消、餐损或责任。

缺口：未确认人身安全，用户会感觉系统只关心订单。

人工侧更优路径：风险 → 情绪 → 方案

先确认是否受伤和是否需要紧急帮助，再明确餐损与违规处理，最后协商用户可接受的最小损失方案。

价值：先处理不可逆风险，再优化业务结果。

如何把“策略顺序”变成奖励

  • 检测到人身风险关键词时，未做安全确认就谈责任或补偿，设置高优先级惩罚。
  • 安全确认完成后仍持续重复关心，给重复和无推进惩罚，避免“过度共情”。
  • 只有在必要槽位齐全时方案校验器才放行；否则话术再自然也不能获得方案完成分。
  • 工具执行成功且对用户如实说明后才给闭环奖励，不能仅依据用户“好的”判断解决。

难点 1：对话策略建模

只看用户是否满意、问题是否解决，无法区分策略质量。例如模型可能用高额补偿快速换取满意，也可能靠模拟器迎合结束会话。原页提出建设可控、可解释的“轨迹策略评估模型”，为整段沟通策略打分并给出原因。

难点 2：方案正确性保障

当前 Rule-Based Reward 和 GRM 主要聚焦话术，方案层往往只靠规则兜底。建议将“知识驱动的 Turn-Level Verifier”与“会话级外部验证器”分开：

  • Turn-Level Verifier：输入当前状态、知识条款、可用工具与候选动作，判断方案是否满足前置条件。
  • Session-Level Verifier：读取完整工具日志与最终状态，验证承诺是否执行、结果是否到账、终止是否正确。
  • 冲突处理：当风格 GRM 认为回复很好，但 verifier 判定方案错误时，正确性必须覆盖风格分。
  • 知识版本化：奖励记录必须绑定政策版本和知识快照，避免用新规则误判旧日志。

难点 3：方案与话术协同优化

“方案正确但时机不对”依然会失败。可把策略拆成两层：高层 planner 选择 安抚 / 澄清 / 核验 / 协商 / 执行 / 升级，低层 generator 生成符合业务风格的话术；奖励分别评估高层动作和低层表达，再通过会话结果联合校准。

07 · 面试表达

别背名词：把多轮 RL 讲成能被连续追问的系统项目

面试回答先给判断，再解释机制、证据和边界。下面的示例只使用前文已核对的原图信息，不把建议方案说成项目已经上线，也不把局部实验包装成普遍结论。

问题 01

为什么智能客服需要多轮 RL，继续做 SFT 不够吗？

我的判断是：SFT 适合教模型“在给定上下文下应该怎么答”，多轮 RL 解决的是“当前动作会改变用户下一步行为，怎样让整段轨迹最终更好”。只要客服动作会改变情绪、信息、工具状态和终止结果，单轮监督就缺少对后续后果的直接优化。

为什么做

局部正确回复可能组成重复、越权或过早终止的坏会话，真正目标是解决率、正确转人工和可执行闭环。

怎么做

用 SFT 建立角色和基本流程，再让当前策略与用户模拟器交互，产生 on-policy 多轮轨迹并按最终结果更新。

边界

多轮 RL 不是 SFT 的无条件替代；模拟器失真、奖励错误或数据覆盖不足时，它会更快放大错误。

证据锚点：P01 业务矛盾 · P02 双流水线 · P07 基线依赖

问题 02

多轮客服的奖励怎么设计，为什么不能直接加权平均？

我的判断是：先把不可妥协的正确性做成硬门控，再用 Turn reward 衡量局部推进，用 Session reward 衡量整段结果。资金、权限、隐私和工具执行一旦错误，不能靠高共情或好文风把总分补回来。

第一层：底线

规则与 verifier 检查方案合法性、用户确认、工具返回和承诺一致性；触发严重错误时截断或重罚。

第二层：过程

轮次奖励判断是否回应诉求、收集必要信息、减少重复并推进状态，而不是只判断语言是否顺滑。

第三层：结果

会话奖励检查最终解决、正确终止、情绪变化和整体连贯性，再通过信用分配定位关键轮。

证据锚点：P03 分层奖励 · P14 Reward hacking · P16 信用分配

问题 03

怎么证明用户模拟器可信，而不是陪策略演戏？

我的判断是：“像真人”只是最低要求，真正有用的模拟器必须让候选策略的离线排序能预测人工盲评或线上 A/B 排序。只报一个图灵测试误识率，无法证明它对训练和模型选择有效。

行为真实性

比较真实与模拟用户的拒绝率、情绪转移、话题切换、终止原因和工具路径分布。

可控与稳定

检查角色一致、正确终止、并发异常、重复输出和提示泄露，并对困难人格做固定回归。

排序有效性

用同一组候选策略测模拟器、人工和线上三方排序相关性，持续监控版本变化后的漂移。

证据锚点：P02 模拟器能力 · P06 离线评估 · P17 工程卡点

问题 04

如果把这项工作当项目介绍，60 秒怎么讲？

我的判断是：项目主线不是“用了 VeRL、vLLM 或 SGLang”，而是把一句话优化改造成可训练、可评估、可上线的服务轨迹闭环。

为什么做

单轮模型会重复询问、缺少长期目标、对流程分支适应不足，因此需要直接优化整段服务结果。

怎么做

从真实难例构造种子任务，训练个性化模拟器；策略并行 rollout；规则、Turn GRM、Session GRM 联合评分；离线 GSB 后灰度上线。

结果与复盘

特定 50 条场景转人工率 64%→46%，100 组话术 G/S/B 为 53/11/36；但对回流 SFT 并非全面领先，仍需补显著性与成本护栏。

完整证据：P05 训练框架 · P08 场景实验 · P09 人工评估 · P19 下一步
